# web-001: Web MIDI port ids and permissions

- Status: accepted
- Date: 2026-10-06
- Canonical source: aud_midi_web, Chrome 153
- Open work: test Firefox and Edge

Web MIDI does not guarantee distinct ids across inputs and outputs, so
`aud_midi_web` prefixes the direction: `webmidi:input:<id>`,
`webmidi:output:<id>`. Headless Chrome rejects `requestMIDIAccess` unless
the feature `BlockMidiByDefault` is disabled (set in `dart_test.yaml` for
the browser tests); SysEx stays denied there and becomes
`MidiPermissionDenied(sysEx)`. `MidiSystemClock` reads `performance.now()`
in the browser, because `Timeline.now` is wall-clock milliseconds under
dart2js and dart2wasm.
